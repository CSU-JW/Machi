# DLC1：海滨假日（首轮测试版）

本文件夹包含新建筑、城镇任务（建议1）、城市事件（2）、角色能力（4）的规则与卡牌素材。以上机制已接入 server.js / engine.js；房间默认关闭DLC，创建房间可勾选开启，也可由等待区第一位玩家（房主）切换。满4人自动开局后锁定模式。没有包含可变市场或快速模式。index.html 是可点击的卡牌图鉴，实际游戏从主站大厅进入。

打开 index.html 可查看所有新卡的点数、价格、颜色、效果，以及任务、事件、角色。catalog.js 是统一数据源；balance.js 可用 `node dlc1/balance.js` 复算期望。assets/cards 保存11张新插画。

## 开局与胜利

四人、原版初始资金与初始建筑不变，新建筑作为额外公共牌堆加入，库存见 catalog.js。每回合仍最多买1张卡、建1个地标，集齐原版四地标立即获胜。博物馆每人限1张，其余新增普通建筑可以重复购买。紫色优先于收益来源分类，紫卡不参与商场交换。

## 新建筑边界

每张独立结算；上限是每张每次触发的上限。新购入的建筑本次不追溯触发。新卡不自动获得商业中心加成（商业中心仍只影响原规则点名的建筑），以免扩大其强度。夜市只从投骰者现有余额取钱，不允许负数；多人收费沿用原版结算顺序。博物馆先于原版6点选择自动结算，不增加选择弹窗。

蓝色建筑种类包括麦田、牧场、林场、渔场、港口；重复卡只算一种。科技园只统计奶制品工厂、工艺品工厂、农产品工厂三种，每种只计一次，自己不算工厂，因此当前实际最高9元，12元为未来扩展保护上限。地标数量最多按3计算，因为第四个建成即结束。

结算顺序：接受最终骰子后，先处理红色收费卡（咖啡店、奶茶店、夜市），同类按玩家座位从1号到4号结算；若为6点，先完成体育馆、电视塔的选择和收费，再发放系统收益（包括博物馆），然后处理商场交换。所有收费以当时现有余额为限；稍后收益不会补缴之前不足的款项。此顺序也适用于原版房间和重投结果。

## 城镇任务

每人一局最多完成1张个人任务。为避免随机抽到过难任务导致不公平，开局每人同时获得入门、进阶、挑战各一张候选，三选一；四人可以重复。角色和任务共用30秒选择阶段，超时选入门任务和首个角色。任务公开，可点击头像查看，后续无需点击领取；每次有效购买、交换、建设完成后自动检查，先检查胜利，未结束才发任务奖励。初始卡计入持有量，条件中的数量必须同时持有。退出或超时不刷新任务。

任务奖励以 catalog.js 为准。入门上限2元、进阶4元、挑战6元，金额是奖励上限，不代表实际回本时间完全相同。任务投入购买的是有收益的建筑，因此不能把全部购卡成本当成净损失来返还。

购卡券只用于普通非紫卡，仍需点数匹配、库存充足且占用当回合购卡次数；地标券仍占用建设次数。均不可转让、兑换现金或找零，最低实际支付1元。一笔交易只能使用一个折扣来源（券、角色或事件三选一），返现与降价合计优惠也受同一限制，避免先折扣再返现。确认购买面板列出可用来源，默认最大可用优惠。支付失败不消耗券或技能。任务发券后最早下个自己的回合可用，防止同回合奖励链。

“便民服务”从完成任务后的下一个自己的回合开始，每次结束回合自动获得1元，共3次，游戏结束后不再发放；无转让、无抵押、无永久被动。此版未添加特殊奖励建筑，避免任务产生无限期收益。

## 城市事件

开局洗混8张事件，第一轮开始揭示1张。一次“轮”是四名玩家各完成一次基础回合；广播中心额外回合属于当前玩家基础回合的延续，不推动轮数，也不刷新事件次数。最后一位玩家及其额外回合结束后才换事件。全部用完重新洗混，避免与上一轮同一事件连续出现。

事件全场共享，所有事件的单人单轮收益/优惠至多1元。获得钱的条件只在最终接受的骰子结果上判断；重投前结果作废。金额奖励是事件独立奖励，不乘卡牌张数、不受商业中心加成。轮初展示横幅，结算自动执行，不新增确认框。

## 角色

开局每人随机获得两个不同的角色候选，二选一，允许不同玩家选择同一角色。角色与任务共用30秒选择阶段，超时自动选首个角色和入门任务。每角色只配置一种主动或被动技能，效果见 catalog.js。所有角色整局经济帮助封顶3元；主动技能只在自己的现有操作面板使用，不打断别人。主界面仅展示自己的任务技能，点击玩家头像查看其他人的介绍。

冷却按角色持有者自己的回合编号计算，含广播中心额外回合：采购员第2回合使用，则第3、4、5回合禁用，第6回合可用；会计第2回合使用，则第3、4回合禁用，第5回合可用。按钮显示“可用/剩余N回合/本局已用完”，购买折扣技能随支付一次确认；会计一次点击即时完成，不创建服务器待选状态。

被动技能不按建筑张数重复发奖，不受商业中心加成。收藏家使用历史已领取阈值集合，交换循环不能刷奖。第四地标胜利检查优先于一切奖励。断线重连保留使用次数、冷却编号、任务和事件领取标记。

## 颜色

绿色＝仅自己的回合从系统获得收益；蓝色＝任何玩家回合从系统获得收益；红色＝从别的玩家收钱；紫色＝每人最多一张（包括紫色特殊卡与地标），优先级最高。颜色用于边框、点数牌、下部渐变和类别文字，兼顾色觉差异。原版客户端也采用同一四色卡面框架。

## 平衡与验收边界

balance.md 与自动输出提供不同投骰阶段的每轮期望。这里的“平衡”是有数学依据的初始版本，不能保证未经实战的胜率平衡。建议记录每种卡购买率、每元投入收益、各角色胜率、任务完成回合与放弃率；每配置至少100局后再调整。若入门任务远比挑战任务划算，优先降低挑战所需的购买次数，而不是提高永久收入。

自动测试覆盖重投只结算最终结果、收费优先、事件额外回合不刷新、技能失败不扣次数、券无法叠加、任务不会重复领取、紫卡不可交换、最后地标立即结束、联网开关权限与重连状态一致。规则实现与平衡性是两回事，最终胜率仍需实战验证。
